## 2026-11-14 R-001 エンジンを速くする

| 測定（同じ機械・Python 3.13・seed 0〜499 のランダム4人戦） | 前の版 | 速い版 |
|---|---|---|
| ランダム1局（3回の測定） | 16.4・16.7・16.5ms | 7.2・7.5・7.3ms（0.44倍） |
| 合法手の生成1回（中盤の局面） | 6.8µs | 1.9µs |
| 複製1回 | 33.1µs | 28.5µs |

- 効いたのは3つ。最長の道を、道を置いた人の分だけ数え直す（前は道1本ごとに全員を数え直し、時間の35%）。
  道を置ける辺・開拓地の場所・交換の比を、盤の形から先に作った表で調べる。産出を出目ごとの表で引く（全頂点を見ない）。
- 結果は前の版と全く同じ: `tests/test_engine_speed.py` が前の版（`tests/ref_game_v0.py`）と500局を並べて打ち、
  毎手の合法手の一覧（並び順も）と、50手ごとの局面・終局を比べる（500局は slow、20局は毎回）。
- 複製はほとんど速くならなかった。時間の大半は乱数の状態の写し（`rng.setstate`）。探索では出目を引き直すので、
  写さない複製を R-006 に足した。
- 再現: `python scripts/engine_speed.py --games 500 --reps 3`

## 2026-11-12 GTO の物差し1: 手番の中の厳密ソルバー

| 対戦・測定 | 対局数 | 結果 |
|---|---|---|
| 貪欲AIどうしの自己対戦で「勝てる手番」を数える | 40 | 勝ち筋のある手番 121 回のうち 86 回（71%）を逃した |
| ソルバー入りAI（`greedy_win`）で同じ測定 | 20 | 逃しは 0 回 |
| `greedy_win` 1人 対 貪欲AI 3人 | 400 | 勝率 32.8%（95%の幅 28.2〜37.3%）→ 基準 25% をはっきり上回る |

- `src/isle/solver.py` の `find_win` は、サイコロのあとの手番の中の手順（建てる・銀行と港の交換・発展カードの使用）を
  全部調べ、この手番で10点に届く筋を探す。発展カードを買う手は運が入るので調べない。
- 逃した例は「道づくりカード＋交換で最長の道を取る」「独占カードで集めて交換して街を2つ」など、
  1手先の評価では見えない数手の組み合わせだった（`scripts/gto_turn_check.py`）。
- 4人のゲームには一つに決まる「理論上の最善（GTO）」はないが、「勝てる手番で勝つ」はどの考え方でも正しいので、
  ここを厳密に解いて物差しにした。

## 2026-11-12 最初のAI（貪欲AI）と重みの合わせ方

| 対戦 | 対局数 | 結果 |
|---|---|---|
| 貪欲AI 1人 対 ランダム3人 | 100 | 貪欲AIが全勝、平均 10.1 点・81.5 手番で決着 |
| 貪欲AI 4人どうし | 100 | 席ごとの勝ち数 20・32・28・20、平均 89.5 手番 |
| 回帰で学んだ重み 1人 対 手の重み3人 | 200 | 勝率 0.5%（大きく弱い）→ 不採用 |
| SPSA で80回合わせた重み 1人 対 手の重み3人 | 400 | 勝率 26.8%（95%の幅 22.4〜31.1%）→ 差がはっきりせず不採用 |

- 貪欲AI（`GreedyAgent`）は評価関数で1手先だけを見る。盗賊は「勝ちに近い相手の産出を止め、自分にはかけない」目安で置く。
  発展カードを買う手は山札をのぞかず、得点カードの割合（5/25）で平均をとる。
- 回帰（各手番の特徴量 → 勝ったか、ロジスティック回帰、約5.4万件）は、勝っている人ほど大きい「近くの空き頂点の価値」に
  大きな重みが付き、村を建てるより空き頂点を残す手を選ぶようになって弱くなった。勝ち負けとの相関は、手を選ぶための重みにはならない。
- SPSA（`scripts/tune_spsa.py`、1回32局×80回）は、1回の勝率差のぶれ（±0.17ほど）が大きく、80回では足りない。
- 次: エンジンを速くして、サイコロを引いて先を読む探索（MCTS）に進む。重み合わせは対局数を増やして自己対戦ループで続ける。
