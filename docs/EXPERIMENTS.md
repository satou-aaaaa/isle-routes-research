## 2026-11-23 R-006 探索用の複製を軽くする（乱数の写しを省く）

| MCTS の測定（読み48回、greedy の対局から取った手番の中の48局面、3回の最短） | 前の版 | この版 |
|---|---|---|
| 探索1回の時間 | 92〜98ms | 99〜101ms（差はぶれの中） |
| 選んだ手（165局面） | — | 前の版と全部同じ |

| 対戦（MCTS 1人 対 greedy_win 3人、席を入れ替え、盤 seed 300000〜、400局） | 勝率 |
|---|---|
| 前の版（main） | 38.2%（95%の幅 33.5〜43.0%） |

- `Game.clone(rng=...)` を足した。int なら新しい seed の Random、Random ならそれをそのまま写しが使う。
  既定の `clone()` は今までどおり乱数まで写し、元と同じに続く（`tests/test_engine_speed.py`・`tests/test_clone_rng.py`）。
- MCTS の決定化（`determinize`）は `clone(rng=rng.getrandbits(64))` にした。前と同じ seed の Random なので、
  選ぶ手は前の版と全く同じ（165局面で一致を確かめた）。
- 複製は速くなったが、MCTS の探索の時間はほとんど変わらない。プロファイルでは時間の75%が評価関数 `features()`、

- 試した案（Random を1つ減らす）は複製がさらに約5µs速いが、探索全体では1%未満で、400局の勝率が 38.2% → 32.5%
  （差は95%の幅の中だが、下がる向き）。得が小さく AI の打ち方が変わるので採らなかった。
- 前の R-003 の記録（36.0%）より前の版の勝率が高いのは、R-007 で相手の greedy_win が変わったため（同じ盤・同じ機械で測り直した）。
- 再現: `python scripts/engine_speed.py --games 50 --reps 1`（最後の行が複製の種類ごとの時間）、
  `python scripts/mcts_match.py --games 100 --workers 4 --sims 48`

## 2026-11-20 R-004 比較相手（公開の強い AI）との橋渡しの設計とルールの違い

比較相手は ROADMAP の公開実装（Python、GPL-3.0-or-later。読んだのは GitHub main のコミット ecf9311、2026-09-08、版 3.3.0）。
コードは読み込まず、取り込まず、このリポジトリの外で動かす。この回はコードを読んで設計と違いの表を作っただけで、比較相手は動かしていない
（外のコードはコンテナでは動かさず、Actions の `research-run.yml` だけで動かす。carcassonne-research R-004 と同じ決まり）。

### 橋渡しのやり方

- 比較相手には、別のプログラムを対局者にする公式の仕組み（exec ボット）がある:
  `catanatron-play --bot ISLE=exec:"python -m isle.bridge" --players AB:2,AB:2,AB:2,ISLE:timeout_ms=5000 --num 20`。
  比較相手が審判になり、こちらのプログラムとは標準入出力で1行1つの JSON を送り合う
  （`hello`→名前と版を返す、`before`→盤全体、`decide`→打てる手の一覧から1つを返す、`step`→ほかの人の手（頼んだときだけ）、`after`→勝者）。
  出典: 比較相手の documentation/advanced/editor.md「Bots in other languages」、catanatron/protocol.py・players/stdio.py。
- こちらのプログラムは比較相手のモジュールを import しない。パイプでのやり取りは「別々のプログラムの間の通信」として扱われる
  （GNU GPL FAQ「Mere aggregation」: https://www.gnu.org/licenses/gpl-faq.html#MereAggregation ）。
  これで NOTICE.md の「GPL のコードは取り込まず、比較相手として別に動かすだけ」を守れる。
- こちら側の仕事（R-010）: ①盤の写し（相手の六角形の座標と頂点・辺の番号 → こちらの `TOPO` の番号。`before` の盤から作る）
  ②局面の写し（建物・道・盗賊・手札・発展カード・最長の道・最大の騎士）③手の写し（こちらの `("build_road", e)` など ↔ 相手の `[色, "BUILD_ROAD", 辺]`）
  ④相手の手札の推定（下の表の「見える情報」）。
- 1手の持ち時間は既定 1000ms で、超えた・反則の手を返した・落ちたときは、その手を比較相手が乱数の手に置き換える（3回続くと残りは全部乱数）。
  R-011 ではこの置き換えの回数を数えて0であることを確かめる。

### ルールの違い（比較相手の既定の設定 と こちらのエンジン）

| 項目 | 比較相手 | こちら | 影響 |
|---|---|---|---|

| 手の形 | 盗賊は「置き場＋奪う相手」を1手、捨て札は1枚ずつ、交換は5枚の組 | 盗賊は置く→奪うの2手、捨て札は1枚ずつ、交換は (出す, もらう) | ルールは同じ。写しで吸収する |

同じもの: 地形・数字・港の数と種類、港の場所（決まった9か所で種類を混ぜる）、建てる費用、駒の数、

発展カードは1手番1枚・買った番には使えない、交換は銀行と港だけ（人どうしの交換の手は出ない）、10点で勝ち、手番1000回で打ち切り。

### 比べ方の制約

- 比較相手の CLI（`catanatron-play`）には対局の seed を渡す口が無い。seed を決めるには比較相手のモジュールを import した
  スクリプトが要り、それは「取り込まない」決まりに反するので使わない。だから「同じ盤・同じ出目の順」で対にした比べ方はできない。
  代わりに `--players` の並びを4通りに回して席を入れ替え、局数を増やして（R-012 は400局以上）運のぶれを抑える。
- 比較相手の pip の最新版（PyPI 3.2.1、2026-11-20）に exec ボットがあるかは未確認。R-011 では読んだのと同じコミット ecf9311 を入れる。
- 続き: R-010（橋渡しのプログラム）→ R-011（Actions で20局）→ R-012（AlphaBeta 3人に400局）。

## 2026-11-17 R-003 サイコロと隠れ札を引いて読む探索（MCTS）

| 対戦（MCTS 1人 対 greedy_win 3人、席を入れ替え、盤 seed 300000〜） | 対局数 | 結果 |
|---|---|---|
| MCTS（読み48回・候補5手・同じ乱数の読み） | 400 | 勝率 36.0%（95%の幅 31.3〜40.7%）→ 基準 25% をはっきり上回る。平均 7.62 点、席ごとの勝ち 38・37・34・35 |
| 同じ設定で「同じ乱数の読み」なし（候補ごとに別の運） | 100 | 勝率 20.0%（95%の幅 12.2〜27.8%）→ 強くならない |

- `src/isle/mcts.py` の `MCTSAgent`。勝てる手番は先に `find_win` で厳密に探し（greedy_win と同じ）、
  それ以外の手番の中の手（MAIN）を探索で選ぶ。サイコロ前・盗賊・捨て札は貪欲AIのまま。
- 1回の読み: 見えない所を引き直す（山の順番と、相手の発展カードの中身を、見えない札の中で配り直す。
  この先のサイコロ・盗むカード・山から引く札は新しい乱数で引く）→ 候補の手を打つ → 全員を貪欲AIで
  自分の次のサイコロの前まで（1巡）進める → 葉の値は4人の評価関数を softmax（温度1）にした自分の割合（勝ちは1、負けは0）。
- 候補は貪欲AIの1手先の評価の上位5手と「手番を終える」。選び方は UCB1（c=0.5）、最後は読んだ回数の一番多い手。
  木は根だけ（ISMCTS の根の部分。Cowling, Powley, Whitehouse 2012）。
- 効いたのは「同じ乱数の読み」（common random numbers）: 候補 i の k 回目の読みは、どの候補でも k 番目の
  決定化・出目を使う。これが無いと、1候補あたり約8回の読みでは運のぶれに手の差が埋もれ、貪欲AIより弱くなった（20%）。
- 速さ: 1局 3.9 秒（MCTS が探索したのは1局で約20回の手番の中の手。4並列で400局 6分40秒）。
  貪欲AIの1手先の評価で乱数を写さない複製を使うようにした（`clone(keep_rng=False)`、結果は同じ）。
- 近似: 相手の手札の資源は見えている扱い（盗まれた札も、数えれば大半は分かるため）。相手の発展カードは
  まだ使っていない分だけを配り直し、手札から見える情報（買った時期など）は使っていない。
- 再現: `python scripts/mcts_match.py --games 100 --workers 4 --sims 48`（`--out` で1局ずつの記録）

## 2026-11-17 R-002 GTO の物差し2: 終盤1巡の読み切り

| 測定（greedy_win どうし40局、誰かが8点以上かつ手番の人が7点以上の局面、1局2局面まで） | max^n | paranoid |
|---|---|---|
| 集めた局面 / 読み切れた局面 | 73 / 40 | 同じ40局面 |
| 最善を打ったときの「この1巡で勝つ確率」（平均） | 13.4% | 12.7% |
| AI（greedy・greedy_win とも同じ値）の同じ確率（平均） | 11.0% | 10.5% |
| 外れ（最善 − AI）の平均 / 最大 | 2.4 / 31.3 ポイント | 2.2 / 32.3 ポイント |
| 外れが1%を超えた局面 / 5%を超えた局面 | 7 / 4 | 7 / 3 |

- `src/isle/round_solver.py` の `RoundSolver` は、手番の人（根）のサイコロのあとから、相手3人の手番と根の次の手番までを
  出目の確率（11通り）どおりに全部読み、「この1巡のうちに根が勝つ確率」を出す。根の手番は全部の手を調べ、
  発展カードを買う手は山の残りの内訳、盗む手は相手の手札の内訳で平均をとる。
- 相手の考え方は2通り（Sturtevant & Korf 2000, AAAI）。max^n: 相手は勝てる手番なら勝つ。7が出たら自分の勝つ確率が
  一番高い盗賊の置き方（同じなら貪欲AIの目安）。paranoid: 7のとき、根の村の近くの置き方の中から根に一番悪いものを選ぶ。
- 近似: 相手は勝てないときは何も建てずに手番を終える。7で手札を捨てるのは決まった規則（一番多い資源から）。
  根の次の手番は「勝てるかどうか」だけを `find_win` で見る（建てて次につなぐ手は数えない）。
- 外れが一番大きかった3局面は、どれもAIが手番を終えたところ（1手目ごとの値を別に読んで確かめた）:
  - 9点で発展カードを買わずに終えた: 勝つ確率 34.7% → 買えば 65.2%、5.1% → 買えば 36.4%。
    貪欲AIは得点カードの割合を山の残りにかかわらず 5/25 とみなし、引いたらすぐ勝つことも評価に入れていない。
  - 9点で道を1本引かずに終えた: 13.4% → 決まった1本で 28.6%（銀行との交換でも 18.4%）。
  - greedy_win は手番の最初に勝ち筋を探すだけなので、どの局面も greedy と同じ値だった（この1巡で勝つ筋はどちらも逃さない）。
- 読み切れなかった33局面は、1局面・考え方1つ600秒の上限に当たった（相手の手札が多く、根が勝ちうる終わり方が多い局面）。
  外れの数字は「読み切れた40局面」の中のもの。
- 速くした部品: 乱数を写さない複製 `clone(keep_rng=False)`（中盤の局面で 25µs → 3µs、乱数を使うと止まる）、
  `could_win`（手札・道・騎士から10点に届きうるかの甘めの上限。届かない局面では `find_win` を始めず、途中でも枝を切る）、
  勝ち筋の有無を盤・手札・使える銀行の枚数で覚える表、盗賊の置き場を「盗む相手ごとに1つ」にまとめる。
  `find_win` は盗む相手を選ぶ場面で読みを打ち切るように変えた（前は乱数で1つ引いていた）。
- 再現: `python scripts/round_check.py --games 40 --workers 4 --per-game 2 --max-seconds 600 --out runs/r002`（4並列で約2時間10分）

| 貪欲AI 4人どうし | 100 | 席ごとの勝ち数 20・32・28・20、平均 89.5 手番 |

| SPSA で80回合わせた重み 1人 対 手の重み3人 | 400 | 勝率 26.8%（95%の幅 22.4〜31.1%）→ 差がはっきりせず不採用 |

- 貪欲AI（`GreedyAgent`）は評価関数で1手先だけを見る。盗賊は「勝ちに近い相手の産出を止め、自分にはかけない」目安で置く。
  発展カードを買う手は山札をのぞかず、得点カードの割合（5/25）で平均をとる。
- 回帰（各手番の特徴量 → 勝ったか、ロジスティック回帰、約5.4万件）は、勝っている人ほど大きい「近くの空き頂点の価値」に
  大きな重みが付き、村を建てるより空き頂点を残す手を選ぶようになって弱くなった。勝ち負けとの相関は、手を選ぶための重みにはならない。
- SPSA（`scripts/tune_spsa.py`、1回32局×80回）は、1回の勝率差のぶれ（±0.17ほど）が大きく、80回では足りない。
- 次: エンジンを速くして、サイコロを引いて先を読む探索（MCTS）に進む。重み合わせは対局数を増やして自己対戦ループで続ける。
